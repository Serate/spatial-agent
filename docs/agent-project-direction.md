# Spatial Agent 项目总体方向

本文档作为持续开发 goal 规划下一阶段任务时的总体参考。阶段任务必须服务于完整 Agent 闭环，不能因为最近出现的单个数据、模型或页面问题而改变项目主线。

## 项目定位

Spatial Agent 是一个可演示、可测试、可扩展的空间智能体系统。GIS 数据是业务载体，核心目标是展示 Agent 的任务理解、计划编排、工具执行、结果解释和可靠运行能力。

## 核心闭环

```text
自然语言问题
  -> 意图识别与必要澄清
  -> 结构化计划与约束校验
  -> 多工具编排与受控执行
  -> 答案、地图、轨迹和数据证据
  -> 会话恢复、异步运行、重试与评测
```

## 必须持续建设的能力

1. **任务与规划**：开放式问题理解、澄清、多步骤计划、依赖关系、计划修复。
2. **工具与架构**：统一 schema、Tool Registry、Planner/Runtime/Backend 解耦和安全边界。
3. **状态与可靠性**：会话历史、异步任务、取消、超时、幂等、重启恢复和可观测性。
4. **结果与证据**：统一 result envelope，关联答案、轨迹、工具结果、GeoJSON、地图图层、数据版本和 provenance。
5. **模型工程**：真实模型可替换、结构化输出校验、失败分类、重试、token/延迟指标和离线回放。
6. **数据与 GIS**：数据健康、覆盖范围、CRS/栅格对齐、manifest 和降级说明；数据问题只能作为系统能力的证据层。
7. **产品体验**：对话驱动、按结果类型动态展示答案、表格、地图、下载项和轨迹，避免固定堆叠无关面板。
8. **测试与部署**：契约测试、端到端评测、浏览器 smoke、真实 GIS 验证、Docker、readiness 和生产接口验收。

## 阶段规划原则

每次规划下一阶段，先从产品、架构、数据、模型、部署、体验、测试七个维度盘点现状、缺口、依赖、风险和验收证据。然后选择能提升完整闭环的阶段目标，再拆分最多 3 个边界清晰的并行任务。

具体数据集、单个工具、一次模型报错或一个页面缺陷，必须明确说明它服务于哪个系统级目标；不能把局部修复本身当作下一阶段目标。

阶段循环固定为：

```text
全局盘点 -> 阶段规划 -> 并行实现 -> 统一集成 -> 分层测试 -> 全局复盘 -> 下一阶段
```

## 面试展示标准

最终演示应能完整回答一个开放式空间问题，并让面试官看到：Agent 如何决策、为什么调用这些工具、结果是否可信、失败如何恢复、系统如何测试和部署。新增功能只有在增强这条证据链时才优先进入规划。
