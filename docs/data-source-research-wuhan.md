# 武汉市/洪山区公开空间数据调研

> 调研日期：2026-08-07
>
> 范围：道路、水体、生态保护区、土地利用编码表。优先记录政府开放数据、官方 API、OpenStreetMap 官方 API/许可文档和自然资源部门标准。未能在本次环境中打开或确认的入口明确标记为“待核验”，不将第三方下载站、数据镜像或搜索结果作为已确认来源。

## 结论摘要

目前最容易直接接入 Demo 的是 OpenStreetMap 官方 API，但它提供的是 OSM 数据对象 XML，不是按业务主题整理好的武汉道路或水体 GeoJSON；需要在本地按标签筛选、转换并记录下载时间和许可信息。其适合作为道路、水系的演示数据源，不应直接表述为武汉市法定基础地理数据。

武汉市政府开放数据门户是道路、水体和生态保护区数据的首选官方目录入口，但本次调研中门户页面请求超时，尚未核实具体数据集、下载地址、字段、许可和 CRS。因此目前不能把它们当作已经可下载的数据源，后续应在能访问门户的网络环境逐项核验。

土地利用“编码含义”不能从现有栅格的数值编码直接推断。应采用自然资源部/国家标准的分类文件，并同时保存数据提供方的编码映射表；如果只有 GB/T 21010-2017 而没有数据集自己的 legend，仍不能安全地把像元值翻译成“耕地、建设用地”等语义。

### GitHub 检索结论

- 未找到带有明确许可证、可直接下载、覆盖洪山区道路/水体/保护区的成熟 GitHub 数据仓库。
- `Supeset/China-GeoData` 可作为行政区边界备用，但当前项目已有真实湖北行政区数据，暂不需要替换。
- `yzengal` 路网仓库没有武汉文件，且格式需要转换，不能直接使用。
- `ViVi141/china-1m-geodata-postgis-mcp` 更适合参考数据接入架构；是否能取得其数据包、数据授权和空间精度必须另行核验。
- 对本项目 Demo，最现实的路线仍是：道路/水体使用 OSM 官方 API 或合法导出，保护区向官方部门或开放门户申请/核验，土地利用补齐数据提供方 legend；GitHub 仓库只作为代码、格式和数据目录参考。

## 推荐接入顺序

1. 先用 OSM 官方 API 做道路和水体的可重复演示采集，并保留原始 XML、bbox、时间和 ODbL attribution。接入前核验 API 当前限制，并用洪山区边界裁切。
2. 同时在武汉开放数据门户核验官方道路、水体和保护区数据。若官方数据可下载且许可明确，优先替换 OSM；若只能在线查看或需要申请，保留 OSM 作为非权威演示源。
3. 对当前土地利用栅格补齐随数据提供方发布的 legend，再用 GB/T 21010-2017 和自然资源部分类指南核对语义。没有 legend 时不输出“耕地/建设用地”等推断名称。
4. 保护区数据最后接入。它对结果解释和责任边界影响最大，必须确认数据时点、发布部门、许可、边界 CRS 和是否为法定红线后，才能作为排除约束。

## 直接拉取验证

调研时间：2026-08-08。

### 武汉市范围

根据本地湖北县级行政区 GeoJSON 中的武汉 13 个区（含洪山区、江夏区、黄陂区等）计算得到外包络框：

```text
min_lon=113.698077
min_lat=29.971928
max_lon=115.076651
max_lat=31.362866
```

这是行政区外包络框，不是严格的武汉市融合边界。下载后仍应使用融合后的武汉市边界裁切，避免把外包络中的周边区域当作武汉市数据。

### OSM API 实测

官方 OSM API 地址：

`https://api.openstreetmap.org/api/0.6/map?bbox={min_lon},{min_lat},{max_lon},{max_lat}`

使用洪山区附近约 `0.02° x 0.02°` 的小范围请求时，在当前网络环境中 60 秒内连接超时，未生成文件。该结果只能说明当前 API 路径或网络对本次客户端不可用，不能据此断言 OSM 没有数据。武汉市完整外包络约 `1.38° x 1.39°`，不应直接作为一个 `map` 请求提交；官方文档也要求对大范围下载采用更合适的导出方式，而不是把 API 当作整市数据导出服务。

### Overpass 小网格实测

公共 Overpass 查询服务成功返回了一个 `0.1° x 0.1°` 样本网格：

`https://overpass-api.de/api/interpreter`

查询主题为 `highway`、`natural=water` 和 `waterway`，使用 `out geom` 返回几何。样本结果约为：

| 类型 | way 数量 |
|---|---:|
| 道路（`highway`） | 11,270 |
| 面状水体（`natural=water`） | 161 |
| 线状水系（`waterway`） | 43 |

该数量表明全市道路和水体对象可能达到百万级，不能用一个请求或一次性内存合并处理。建议将武汉外包络切成 `0.05°-0.1°` 网格，逐格请求并在本地按 OSM element 的 `type+id` 去重；每个网格保存原始 JSON、查询时间、bbox 和响应校验信息，失败网格支持重试和断点续传。

Overpass 不是 OSM 数据许可的替代品。导出的 OSM 数据仍受 ODbL 1.0 约束，产品页面和导出文件应保留 OpenStreetMap attribution，并记录数据时间和查询范围。来源：

- OSM API 文档：https://wiki.openstreetmap.org/wiki/API_v0.6
- OSM 版权与 ODbL 说明：https://www.openstreetmap.org/copyright
- Overpass API 文档：https://wiki.openstreetmap.org/wiki/Overpass_API

### 结论

**可以拉取整个武汉市的道路和水体演示数据，但应采用分块 Overpass 或可访问的区域 PBF，不应直接请求武汉市外包络的 OSM API。** 当前最稳妥的落地顺序是：先用 0.05° 网格验证断点下载器，再扩大到全市；下载完成后转换为 GeoPackage，建立空间索引，并在项目数据登记表中记录来源、时间、CRS、许可和裁切边界。
