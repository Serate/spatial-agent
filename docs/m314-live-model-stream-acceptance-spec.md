# M314 Spec：真实模型流式交互与答案质量验收

## 目标

在 Docker、真实中转模型和真实本地 GIS 数据上验证 Agent Runtime 的实时阶段事件、
SSE 续传、失败恢复、最终答案增量输出和用户可读性。发现问题时只修复公共契约或
真实边界，不增加单一问句或区域的硬编码分支。

## 约束

- 单 Agent、并发度 1；默认测试离线且精简，真实模型验收显式执行。
- Provider 单次请求预算约 45 秒，最多 1 次自动重试；不循环消耗 token。
- 不保存或输出 API key、Prompt、模型原文、隐藏思维链、完整异常堆栈和私有路径。
- 计划、工具参数和结果必须先通过既有 catalog、workflow、TaskPlan、ToolRegistry、
  execution binding 和 Result/Evidence 门禁。

## 验收契约

每个 Run 必须能按序产生可恢复的 `RunEvent v1`，并在事件中区分规划等待、工具执行、
答案生成、完成、澄清和失败。答案流只能来自已校验的最终答案边界；前端允许逐字呈现，
但不得把动画当作后端进度。终态 Result、Evidence、artifact 和事件流必须保持一致。

## 场景

1. 简单 GIS 元数据查询成功。
2. 同一会话的经济指标连续追问。
3. 洪山区边界、DEM/坡度、道路、水体与 2024/2025 经济指标的开放式多组件分析。
4. 缺少指标或时间范围时返回字段级澄清且不创建执行 Run。
5. 受控 Provider 超时、失败提示、重试和恢复。
6. SSE 断线、`Last-Event-ID` 续传、轮询降级与容器重启恢复。
7. 真实答案 delta 流，以及不支持流式 Provider 的完整答案 fallback。

每个场景只记录状态、阶段、计数、耗时、错误类别、streaming 标志和指纹；成功答案
只做脱敏可读性断言，不持久化原文。

## 成功标准

- 规划阶段超过等待阈值时有心跳、耗时和可恢复提示，不显示为假死。
- 成功 Run 在终态前产生多个阶段事件和多个 `answer_delta`，答案队列排空后才完成。
- 断线重连不重复、不跳过事件；服务重启后仍可恢复事件和最终结果。
- 回答使用自然中文，突出结论、关键发现、来源和限制，不以工具步骤计数作为主要答案。
- Provider 失败、澄清、fallback 和 GIS 数据不可用均返回明确的用户级说明。
