# M330 能力图：通用 Agent 开放问题质量与纵向行为验收

## 阶段目标

从项目全局验证 M329 形成的通用 Runtime 是否真正表现为通用 Agent：用户可以提出没有预设关键词的问题，系统能够在
直接回答、已登记能力、白名单网页、受控工具提案和结构化澄清之间做出合适选择，并给出自然、诚实、可恢复的结果。

本阶段不新增针对某个地区、固定问句或单一数据集的分支；不引入 RAG。重点是把已有 Runtime 的能力、边界和用户体验
连成可验收的纵向行为。

## 全局能力面

| 能力面 | 本阶段关注点 | 交付物 |
| --- | --- | --- |
| 产品 | 普通问题默认可用，结果简洁且突出结论 | 场景矩阵、用户答案约束 |
| Runtime | 直接回答/工具行动/澄清/审批/降级状态不混淆 | 行为规则与状态投影 |
| Planner | 不依赖固定关键词；能利用能力目录选择动作 | 受控选择与澄清验收 |
| 工具治理 | 只调用已注册工具；新工具必须提案、沙箱、人工审批 | proposal/approval 验收 |
| 数据与证据 | 有数据就引用事实，无数据就说明限制，不伪造来源 | Result/Evidence 对照 |
| 模型与上下文 | 真实模型结构化动作合法，答案不泄露 Prompt/思维链/内部状态 | live receipt 与答案检查 |
| 传输与恢复 | CLI、HTTP、SSE、轮询、Artifact、重启核心结果一致 | 跨入口验收报告 |
| 前端 | 用户优先展示结论，过程和证据可展开，流式期间有真实进度 | Console projection 验收 |
| 测试与交付 | 默认离线精简，真实模型/Docker 单独验收 | 分层命令与交接文档 |

## 场景层级

1. 无数据的概念、解释、比较和写作请求：直接回答，不制造工具步骤。
2. 单领域事实请求：从目录选择一个已登记工具，结果为空或不可用时诚实降级。
3. 跨领域请求：组合多个已登记能力，保留每个结果类型和证据 owner。
4. 公共网页请求：仅对白名单域名搜索，网络失败不伪造来源。
5. 未登记能力请求：给出直接知识回答、澄清或受控工具提案，不静默拒绝整个问题。
6. 需要审批的提案：审批前不执行；审批后恢复同一 Run，并保留可读 lineage。
7. Provider/数据故障：保留已完成部分，明确缺失部分和可恢复动作。

## 非目标

- 不允许任意 URL、任意代码执行、自动发布模型生成工具或绕过工具 schema/权限/审批。
- 不保存原始 Prompt、隐藏思维链、密钥、网页正文或工具 source。
- 不为测试场景增加硬编码问句路由；测试 fixture 只验证公共契约。
