# M326 能力图：开放式 ReAct 稳定交付

## 阶段目标

让通用 Agent Runtime 在开放式请求中稳定完成“理解 → 发现能力 → 多步动作 → 受控校验 →
真实执行 → 完整或部分答案”的闭环。GIS 继续作为验收载体，但本阶段不为洪山区、DEM 或固定
问句增加专用分支。

## 能力边界

| 能力 | 公共 Runtime | Domain Pack | 外部边界 |
|---|---|---|---|
| ReAct 轮次、预算、历史和恢复 | 负责 | 提供目录与策略 | 不暴露隐藏思维链 |
| 工具发现、schema、权限和审批 | 通过 ToolRegistry | 声明工具与数据依赖 | 不允许模型绕过 Registry |
| Workflow/template 约束 | 解释并执行通用政策 | 声明可选蓝图与领域门禁 | 不把单模板当作 Runtime 能力边界 |
| 完整/部分/阻塞结果 | 统一契约 | 提供事实与限制 | 前端消费结构化状态 |
| 答案生成 | 使用公共输入投影 | 提供领域事实 | 不输出 Prompt、原始响应或敏感数据 |
| SSE、轮询、artifact、重启恢复 | 共享事件与结果 | 无传输逻辑 | 各入口核心结果一致 |

## 主要切片

1. ReAct 增量动作与 Domain workflow policy 解耦，但保留执行策略、权限、审批、数据就绪和预算门禁。
2. 将动作校验失败、工具失败、模型规划失败统一投影为可审计的部分结果或阻塞结果。
3. 让答案生成明确知道结果完整性、停止原因和已完成事实，避免把部分结果写成“全部完成”。
4. 在不新增固定关键词分支的前提下，使用真实模型 + Docker/GIS 验证至少两类开放请求。
5. 对 CLI、HTTP、SSE、轮询、artifact、前端和重启恢复做一次最小充分的一致性验收。

## 非目标

- 不在本阶段引入 RAG、知识库或任意网页抓取。
- 不允许模型直接执行未注册工具、任意 URL 或未经审批的生成代码。
- 不把真实数据复制到仓库，不把真实 Provider 调用放进默认 CI。
