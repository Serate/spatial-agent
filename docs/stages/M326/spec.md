# Spec：M326 开放式 ReAct 稳定交付

## 背景

M325 已证明真实模型能够进入 Docker/GIS 运行链路，并能够在后续动作校验失败时安全收束。
但真实请求仍可能因为静态 workflow/template 的增量约束过早停止，且部分结果的最终答案需要更
清楚地表达完成范围。M326 解决通用 Runtime 的这两个问题，不复制 GIS 专题流程。

## 需求

### 1. 增量规划与策略边界

- ReAct 每轮产生的 TaskPlan 增量必须通过同一个公共校验入口。
- 领域 workflow/template 可以提供约束和建议，但不能把某一个唯一模板的步骤数量误当成开放式
  ReAct 的全部能力边界。
- 执行策略、工具 allowlist、schema、权限、审批、数据 readiness、依赖证据和轮次/动作预算必须
  继续有效；任何策略类错误都必须 fail closed。
- Runtime 不得根据区域名称、固定关键词或模型原文猜测工具。

### 2. 结果完整性

- ReAct run evidence 必须区分 `complete`、`partial`、`blocked` 和等待决策等状态。
- 触发部分恢复时，必须记录停止原因、已完成动作数量和未完成动作不确定性；不得声称未执行步骤
  已完成。
- 同一状态应被同步执行、异步轮询、SSE、artifact、SQLite 恢复和前端投影共同消费。

### 3. 答案生成

- 答案生成输入只包含脱敏后的用户请求、结构化事实、结果完整性和证据摘要。
- 完整结果应给出通俗结论；部分结果应明确说明“已完成什么、还缺什么、是否可以重试”。
- 失败或阻塞结果不能被答案生成器包装成成功结论。

### 4. 验收与恢复

- 默认测试保持离线、精简；只运行受影响契约和必要集成验收。
- 显式真实验收至少覆盖一个多步 GIS 请求和一个不同结果形态的开放请求。
- 真实 Docker 运行应验证 SSE、Last-Event-ID、轮询、artifact 和重启恢复的核心字段一致。

## 安全与隐私

- ToolRegistry 是唯一工具发布和 dispatch 边界。
- 网络仅允许服务器配置的 HTTPS 白名单域名；模型不能提供 URL、headers 或 HTTP 方法。
- 生成工具必须经过 AST、沙箱和人工审批；本阶段不改变审批策略。
- 不保存或输出 API key、Prompt、模型原文、生成源码和完整私有数据。

## 验收标准

1. 一个不依赖固定关键词的开放请求可以连续执行多个已注册工具，或明确返回可恢复的部分结果。
2. workflow/template 不再错误阻断合法的开放式 ReAct 增量动作，但所有治理门禁仍有效。
3. 部分结果的答案、evidence、artifact、SSE 和前端状态均能表达完成范围与停止原因。
4. 策略/审批/权限错误仍被阻断，不会因已有部分证据而自动放行。
5. Docker 真实模型 + GIS 纵向验收和最小跨入口恢复验收通过。
