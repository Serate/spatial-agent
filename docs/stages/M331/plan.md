# Plan：M331 真实模型开放任务可靠性与通用能力可用率

> 顺序：全局规划 → Spec → 模型/Runtime 可靠性 → 通用组合 → 上下文恢复 → 答案体验 → Docker/live 验收 → 交付/全局重规划。
> 单 Agent，最大并发度 1；每阶段任务集中安排，测试按风险合并，默认只运行最小充分验证。

## M331-0：阶段初始化

- [x] 建立 capability map、Spec、Plan、handoff。
- [x] 将恢复入口切换到 M331，只保留热状态、当前 handoff 和必要规划文件。
- [x] 从产品、Runtime、Planner、Domain、数据、模型、部署、体验和测试全局确定可靠性优先级。

## M331-A：模型协议与有限修复

- [ ] 汇总真实模型常见的结构化输出漂移，建立脱敏 conformance 场景矩阵。
- [ ] 统一 planner/ReAct/answer 的解析、compact retry、字段修复和失败分类，不重复调用无意义的 fallback。
- [ ] 验证错误结果类型、漏字段、额外字段、截断 JSON 和 provider timeout 的有限修复/安全终止。
- [ ] 保持计划和工具参数只有完整校验后才能进入执行或前端展示。

## M331-B：通用任务组合与结果闭合

- [ ] 验证能力目录可支撑直接回答、单域、多域和混合任务，不增加关键词路由。
- [ ] 完善工具操作到 Result profile 的声明式推导；多义关系必须澄清或 fail-closed。
- [ ] 验证依赖、权限、预算、preflight、工具执行和结果 owner 在每一步一致。
- [ ] 验证部分成功、无结果、不可用和多结果类型能够统一汇总为可读答案与 evidence。

## M331-C：上下文、长任务与恢复可用率

- [ ] 为多轮和长任务建立有界上下文预算、摘要和安全历史投影，不保存 Prompt/思维链。
- [ ] 验证预算耗尽、取消、重试、澄清续跑、审批恢复和服务重启的同一 Run/session identity。
- [ ] 验证事件、Artifact、SQLite 和 SSE 回放在裁剪/恢复后不重复、不丢终态和关键 evidence。

## M331-D：答案质量与实时体验

- [ ] 建立不依赖具体领域的答案质量检查：结论优先、自然中文、长度适当、事实边界清晰。
- [ ] 验证直接回答、部分结果、降级、等待确认和失败状态的答案不会混淆。
- [ ] 验证 token/delta 流、阶段心跳、工具状态、证据和结构化视图在 CLI/HTTP/前端一致。

## M331-E：阶段验收

- [ ] Docker 运行一组覆盖独立失败模式的合并紧凑回归，不按每个场景重复全量测试。
- [ ] 运行 compileall、architecture strict、code/document index、readiness 和前端/事件 smoke。
- [ ] 真实模型完成直答、单域/跨域、多步、Web/降级、提案/审批、多轮/恢复的代表性验收。
- [ ] 报告只保留脱敏状态、计数、结果类型、evidence、repair lineage 和事件序列。

## M331-F：交付与全局重规划

- [ ] 更新热状态、任务账本、M331 handoff、里程碑和索引。
- [ ] 提交并推送阶段版本；不将私有配置或 live 输出纳入提交。
- [ ] 根据全局目标规划下一阶段，继续控制测试规模和上下文读取范围。
