# M331 能力图：真实模型开放任务可靠性与通用能力可用率

## 阶段目标

在 M330 已打通通用入口和受控行动的基础上，提高真实模型面对开放式任务时的成功率、可恢复性和答案质量。
重点是让公共 Runtime 更能承接模型的不稳定输出与长任务，而不是继续为某个领域、地区或数据集增加固定分支。

## 全局能力面

| 能力面 | 关注点 | 交付物 |
| --- | --- | --- |
| 产品 | 大多数合理问题都能得到回答、澄清或可执行下一步 | 开放任务成功率场景矩阵 |
| Runtime | 规划、动作、执行、回答和恢复状态不丢失 | 可靠性状态与 repair lineage |
| Planner/模型 | 结构化输出漂移、漏字段、错误结果标签可有限修复 | provider conformance 与 bounded repair |
| 工具治理 | 能力发现、参数/依赖/权限/预算/结果契约继续集中校验 | 通用组合验收 |
| 上下文 | 多轮、长任务、审批和重启保持有界且一致 | context budget 与恢复对照 |
| Domain/Data | Domain 只提供能力声明和事实，Runtime 不携带领域策略 | Domain onboarding contract |
| 答案/体验 | 真实进展、结论、证据和限制清晰，答案流可用 | 脱敏质量评估与前端投影 |
| 部署/测试 | Docker/live 显式验收，默认测试最小充分 | 分层验收报告 |

## 纵向链路

请求 → 事实/能力上下文 → 结构化计划或 ReAct 动作 → 有界修复 → schema/权限/预算/preflight → 工具执行 →
Result/Evidence → 流式答案 → SSE/Artifact/恢复。每个边界都必须保留稳定身份、状态和失败原因，但不能传播 Prompt、
隐藏思维链、密钥、网页正文或工具源码。

## 非目标

- 不引入 RAG、任意网络、任意 shell、自动上线模型生成工具或绕过审批。
- 不通过关键词表覆盖所有问题，不把“提高可用率”实现成大量固定问句分支。
- 不在这一阶段重写 GIS 算法或迁移前端框架；只有当公共契约存在缺口时才修改对应 seam。
