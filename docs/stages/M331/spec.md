# M331 Spec：真实模型开放任务可靠性与通用能力可用率

## 目标

让真实模型在开放请求中更稳定地完成“理解—计划/行动—校验—执行—证据—回答”链路；遇到模型输出不完整、工具不可用、
事实不足或任务过长时，有限修复、澄清、降级或恢复必须比直接失败更可用，同时保持安全边界。

## 行为契约

- Planner、ReAct、ToolRegistry、Result、Evidence、RunEvent、Artifact 和前端继续使用版本化公共契约。
- 模型输出不是权限来源。所有工具、参数、依赖、结果类型、网络、预算和提案都要经过 Runtime/Registry 校验。
- 只对可判定的结构化缺陷进行有限修复；超过次数、预算或语义边界时安全停止并返回可读原因。
- 可信能力目录或已校验 workflow 可以推导结果类型；多个候选无法唯一确定时必须澄清或拒绝，不能猜测。
- 长任务、多轮补充、审批恢复、取消、重试和服务重启保持同一 run/session identity 及可读 lineage。
- 通用问题不依赖关键词命中；需要外部事实时必须有工具或 Web evidence，无法获取时明确说明范围和限制。
- 用户答案先给结论，再给关键依据、限制和下一步；不输出工具名、内部状态、Prompt、隐藏思维链或敏感信息。

## 首版验收范围

1. 真实模型结构化计划/动作的常见字段漂移、错误包裹、缺失结果类型和一次有限修复。
2. 单域、跨域、多步、直接回答、澄清、Web 降级和工具提案审批的稳定公共投影。
3. 多轮续问、长上下文裁剪、预算耗尽、取消、重试、SQLite/Artifact 重启恢复。
4. CLI、HTTP、SSE、轮询、前端和 Artifact 的核心结果/evidence 一致性。

## 安全与数据边界

网络继续使用公共白名单；工具提案继续 sandbox + 人工确认；真实数据只按显式挂载使用；验收报告只保存脱敏状态、计数、
结果类型、reason code、evidence 状态和事件序列，不保存模型原文、Prompt、密钥、网页正文或工具源码。
