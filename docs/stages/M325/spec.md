# Spec：M325 真实模型 + Docker/GIS + 白名单搜索纵向验收

## 目标

验证当前 Agent Runtime 已经能够在真实部署边界完成开放式任务：真实模型理解请求并逐轮
选择已登记能力，Docker 中的 GIS 后端读取真实本地数据，必要时调用白名单网页搜索，所有
动作经过统一校验、预算、证据、结果和恢复链路，用户最终看到的是可读答案和结构化结果。

本阶段优先暴露集成问题，不以增加工具数量为目标；如果已有 seam 不足，优先补通用边界，
不得为单一问句增加关键词分支。

## 公共契约

1. Planner/ReAct 继续输出经过 schema 校验的 `TaskPlan` 或 `ReactDecision`。
2. 工具只通过 `ToolRegistry` dispatch；工具提案遵循 M322～M324 的审批状态机。
3. 搜索结果使用 `spatial-agent.document-evidence.v1`，来源仅限服务器白名单。
4. 运行结果使用已有 Result、Evidence、Artifact 和 RunEvent 版本化契约；不新增隐藏思维链
   字段，不持久化 Prompt、完整模型原文、密钥或网页原文。
5. HTTP、CLI、SSE、轮询、artifact 和重启恢复只能改变传输方式，不能改变核心结果和证据。

## 首个验收请求

使用一个明确但开放的请求，不绑定固定工具顺序：

> 请分析洪山区的地形与道路可达性：先确认可用数据和覆盖范围，再统计 DEM 的高程概况，
> 计算道路附近区域的空间结果；如果本地数据不足，说明缺失项，不要把演示结果当成规划许可
> 结论。必要时查找公开数据说明，但只使用系统允许的来源。

该请求同时验证数据探测、栅格/矢量结果、ReAct 多步决策、降级说明和安全搜索边界；不要求
模型臆造“最近经济数据”或自动下载数据。

## 实施任务

- A：确认 provider 配置、真实模型结构化输出和有限预算的显式探针可运行。
- B：确认 Docker 生产容器加载 local GIS 配置、数据目录和 analysis-ready 状态，并形成安全
  数据健康摘要。
- C：将白名单搜索配置接入显式验收，分别覆盖成功、空白白名单、越界域名和网络错误。
- D：运行一次真实模型 + Docker/GIS 的 ReAct 纵向请求；保留安全 receipt、事件和最终结果摘要。
- E：验证结果在 HTTP/轮询/SSE 或 artifact/重启路径中的核心字段一致；失败时分类为配置、
  provider、规划、工具、数据或传输问题。
- F：阶段收口，记录真实验收证据，必要时只修复发现的通用集成缺口并重新验证。

## 安全与降级

- 真实模型调用需显式环境开关和命令参数，默认测试不调用网络。
- 任何配置缺失只返回 `unavailable`/`degraded` 及有界原因码；不输出 key、Prompt、模型原文
  或本地私有路径细节。
- 搜索适配器拒绝非 HTTPS、IP、localhost、未登记域名、越界重定向和超大响应。
- GIS 未就绪时继续保留可解释的部分事实，但不得捏造像元、几何或规划结论。

## 验收标准

1. 显式真实 provider 探针能成功或返回可分类的安全失败，不产生未校验计划。
2. Docker/GIS 能返回真实数据健康状态和至少一个真实结果，或明确报告缺失/不可用原因。
3. 搜索成功时所有来源在白名单内；策略失败时无越界请求且结果为结构化降级。
4. 真实模型请求至少产生可审计的多个阶段/动作；最终答案不暴露内部思维链。
5. 结果、evidence、artifact 和恢复读取不包含密钥、Prompt、源码或网页原文。
6. 默认精简验证保持离线；真实模型、Docker/GIS、搜索和浏览器只在本阶段显式验收。
